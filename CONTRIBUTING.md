# Contributing Guidelines

## Branch Strategy

- main: Stable, release-ready code
- develop: Integration and development branch
- feature/*: New application features
- fix/*: Bug fixes
- docs/*: Documentation changes

## Branch Naming Examples

feature/user-registration
feature/transport-availability
feature/booking-management
fix/booking-validation
docs/update-readme

## Development Workflow

1. Create a feature branch from develop.
2. Implement and test the changes.
3. Commit using meaningful messages.
4. Push the feature branch to GitHub.
5. Open a pull request targeting develop.
6. Review the changes and resolve feedback.
7. Merge after successful review.

## Commit Message Convention

feat: Add new functionality
fix: Correct an application defect
docs: Update documentation
test: Add automated tests
chore: Update configuration
